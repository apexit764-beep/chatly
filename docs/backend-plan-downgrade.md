# تخفيض الباقة المجدول — مواصفات الباك إند

هذا المستند يصف ما تنفّذه الواجهة حاليًا (ببيانات تجريبية داخل المتصفح) ويحدّد ما يلزم الباك إند لتنفيذه فعليًا.
المرجع في الكود:

| الملف | الدور |
|---|---|
| `src/types/index.ts` | نماذج `Subscription` و`Agent` و`Channel` و`Invoice` |
| `src/store/useAdminStore.ts` | `schedulePlanChange` · `updatePlanChangeKeep` · `cancelPlanChange` · `markPlanChangeReminded` · `applyPlanChange` · `renewSubscription` |
| `src/store/useDataStore.ts` | `suspendForPlan` · `restoreFromPlan` |
| `src/utils/planDowngrade.ts` | `seatedAgents` · `runningChannels` · `downgradeOverflow` · `resolveKeep` · `lostFeatures` |
| `src/utils/planChannels.ts` | `channelTypeAllowed` — أنواع القنوات المسموحة لكل باقة |
| `src/hooks/usePlanChangeScheduler.ts` | المهمة المجدولة: التذكير قبل ٣ أيام، والتنفيذ في الموعد، والاستعادة عند الترقية |
| `src/components/billing/DowngradeDialog.tsx` | نافذة اختيار ما يبقى مفعّلًا وتأكيد التخفيض |

---

## ١. الفكرة باختصار

- التخفيض **لا يُنفَّذ فورًا**. يُجدوَل لنهاية الفترة الحالية (`currentPeriodEnd`)، ويبقى العميل على باقته الحالية بكامل مزاياها حتى ذلك التاريخ.
- لا يُخصم أي مبلغ عند الجدولة. تُنشأ فاتورة بحالة `scheduled` مستحقّة في تاريخ التحويل.
- إذا كان لدى العميل موظفون أو قنوات أكثر مما تسمح به الباقة الجديدة، يختار **ما يبقى مفعّلًا**. ما لم يختره **يتوقف ولا يُحذف**.
- يستطيع العميل تعديل اختياره أو إلغاء التخفيض كاملًا في أي وقت قبل الموعد.
- عند الترقية لاحقًا يعود ما توقف تلقائيًا، في حدود الباقة الجديدة.

## ٢. حدود الباقات

| الباقة (`tier`) | الموظفون | القنوات | أنواع القنوات المسموحة |
|---|---|---|---|
| `starter` | 3 | 1 | `whatsapp` · `widget` · `email` · `gmail` · `outlook` · `yahoo` · `smtp` |
| `pro` | 10 | 3 | ما سبق + `messenger` · `instagram` · `telegram` · `tiktok` |
| `business` | 25 | 10 | جميع الأنواع |
| `enterprise` | بلا حد (`-1`) | بلا حد (`-1`) | جميع الأنواع |

- القيمة `-1` تعني بلا حد.
- ترتيب الباقات: `starter < pro < business < enterprise`.

## ٣. نموذج البيانات

### ٣.١ `Subscription.scheduledChange` (جديد)

```ts
scheduledChange?: {
  planId: string;                       // الباقة الجديدة
  billingCycle: 'monthly' | 'yearly';   // دورة الفوترة الجديدة
  effectiveAt: string;                  // ISO — يساوي currentPeriodEnd وقت الجدولة
  keepAgentIds?: string[];              // الموظفون الذين يبقون مفعّلين (عند تجاوز الحد فقط)
  keepChannelIds?: string[];            // القنوات التي تبقى مفعّلة (عند تجاوز الحد فقط)
  remindedAt?: string;                  // ISO — وقت إرسال تذكير «قبل ٣ أيام»، يُضبط مرة واحدة
}
```

- يوجد تحويل مجدول واحد فقط لكل اشتراك. الجدولة الجديدة تستبدل السابقة.
- يُحذف الحقل عند تنفيذ التحويل أو عند إلغائه.
- `keepAgentIds` و`keepChannelIds` غير موجودين إذا لم يتجاوز العميل أي حد.

### ٣.٢ `Agent.planSuspended` و`Channel.planSuspended` (جديد)

```ts
planSuspended?: boolean;   // true = أُوقف بسبب تخفيض الباقة، لا يدويًا
```

يميّز هذا الحقل ما أوقفه التخفيض عمّا أوقفه العميل بنفسه، لأن الاستعادة التلقائية عند الترقية **تشمل الأول فقط**.

| | الحالة عند الإيقاف بسبب التخفيض |
|---|---|
| الموظف | `invitationStatus = 'suspended'` · `planSuspended = true` · `status = 'offline'` |
| القناة | `status = 'disconnected'` · `planSuspended = true` |

### ٣.٣ `Invoice.status` — قيمة جديدة `scheduled`

فاتورة لم يحن موعد تحصيلها بعد. تُنشأ عند الجدولة وتُحصَّل في `effectiveAt`.

### ٣.٤ `Subscription.discount` (موجود في النموذج — **معطّل حاليًا**)

```ts
discount?: { percent: number; periods: number; acceptedAt: string };
```

يخص «عرض الاحتفاظ»، وهو معطّل في الواجهة حاليًا (انظر القسم ١٢). لا يلزم تنفيذه الآن.

## ٤. من يُحتسب ضمن الحد

يُحتسب ضمن حدود الباقة (في الجدولة وفي التنفيذ وفي فحص الإضافة اليومي):

- **الموظفون:** كل من `invitationStatus != 'suspended'`، **ويشمل ذلك الدعوات المعلّقة (`pending`)**، لأنها تحجز مقعدًا.
- **القنوات:** كل قناة `planSuspended != true`.

ما أوقفه التخفيض لا يحجز مقعدًا. لذلك يستطيع العميل إضافة موظف أو قناة جديدة ما دام العدد الفعلي تحت الحد.

---

## ٥. متى يُعدّ التغيير تخفيضًا

في صفحة الاشتراك، يُعدّ التغيير تخفيضًا إذا تحقق ما يلي:

1. الباقة المختارة ليست الباقة الحالية.
2. الباقة المختارة ليست `enterprise` (هذه تمر عبر «تواصل مع المبيعات»).
3. سعر الباقة الجديدة **لا يزيد** على سعر الباقة الحالية، والمقارنة بنفس دورة الفوترة المختارة وبعملة دولة العميل.

إذا زاد السعر فهو ترقية، والترقية **فورية** وخارج نطاق هذا المستند.

## ٦. واجهات API المقترحة

> الأسماء والمسارات اقتراح. المطلوب هو السلوك.

جميع العمليات تتطلب صلاحية `billing.manage`. أما العرض فيكفيه `billing.view`.

### ٦.١ معاينة التخفيض

```
GET /subscriptions/current/downgrade-preview?planId=…&cycle=monthly|yearly
```

تُرجع ما تحتاجه النافذة لعرض الاختيار:

```json
{
  "effectiveAt": "2026-11-13T00:00:00Z",
  "newPrice": 29, "currentPrice": 79, "currency": "OMR",
  "overflow": { "agents": true, "channels": false, "blockedTypes": true, "any": true },
  "limits": { "agents": 3, "channels": 1 },
  "agents":   [{ "id": "a1", "name": "…", "isOwner": true,  "invitationStatus": "active",  "createdAt": "…" }],
  "channels": [{ "id": "c1", "name": "…", "type": "instagram", "allowed": false, "createdAt": "…" }],
  "defaultKeep": { "agentIds": ["a1", "a2", "a3"], "channelIds": ["c2"] },
  "lostFeatures": ["…"]
}
```

- `defaultKeep` يُحسب بخوارزمية `resolveKeep` (القسم ٧).
- `allowed` يعني أن نوع القناة مسموح في الباقة الجديدة.
- `lostFeatures` هي المزايا الموجودة في الباقة الحالية وغير الموجودة في الجديدة. تُستخدم للعرض فقط.

### ٦.٢ جدولة التخفيض

```
POST /subscriptions/current/scheduled-change
{ "planId": "plan_starter", "billingCycle": "monthly",
  "keepAgentIds": ["a1","a2","a3"], "keepChannelIds": ["c2"] }
```

ما يحدث:

1. التحقق من صحة الطلب (القسم ٨).
2. حفظ `scheduledChange` مع `effectiveAt = currentPeriodEnd`.
3. حذف أي فاتورة `scheduled` سابقة لهذا الاشتراك.
4. إنشاء الفاتورة المجدولة (القسم ١٠).

ملاحظات:

- أرسل `keepAgentIds` و`keepChannelIds` فقط عندما يتجاوز العميل أحد الحدود (`overflow.any = true`). إن لم يتجاوز فلا تُرسل.
- لا تغيير على الموظفين أو القنوات في هذه المرحلة.

### ٦.٣ تعديل ما يبقى مفعّلًا

```
PATCH /subscriptions/current/scheduled-change
{ "keepAgentIds": [...], "keepChannelIds": [...] }
```

- يحدّث القائمتين فقط. لا يغيّر الباقة ولا الموعد ولا الفاتورة.
- يُرفض إذا لم يوجد تحويل مجدول.
- تحقّق القسم ٨ نفسه ينطبق هنا.
- في الواجهة يظهر زر «تعديل ما يبقى مفعّلًا» فقط إذا كان هناك تجاوز للحدود.

### ٦.٤ إلغاء التخفيض

```
DELETE /subscriptions/current/scheduled-change
```

- يحذف `scheduledChange`.
- يحذف الفاتورة المجدولة المرتبطة.
- لا يمس الموظفين ولا القنوات، لأنها لم تتغير أصلًا.

### ٦.٥ قراءة الاشتراك

يجب أن يتضمن `GET /subscriptions/current` الحقل `scheduledChange` كاملًا (مع اسم الباقة الجديدة وسعرها)، لأن صفحة الفوترة تعرض شريط «تحويل مجدول» اعتمادًا عليه.

## ٧. خوارزمية تحديد ما يبقى مفعّلًا (`resolveKeep`)

تُستخدم في موضعين:

- لاقتراح الاختيار الافتراضي في المعاينة.
- عند التنفيذ، لإكمال الاختيار أو تصحيحه.

**النتيجة دائمًا ممتلئة حتى الحد ولا تتجاوزه.**

**الموظفون** (من غير الموقوفين، والدعوات المعلّقة ضمنهم):

1. المالك (`roleId = 'role_owner'`) يبقى دائمًا، ولا يُحتسب اختياره على العميل.
2. يليه من اختارهم العميل في `keepAgentIds` وما زالوا موجودين وغير موقوفين.
3. ما تبقّى من مقاعد يُملأ بالأقدم.
4. العدد النهائي = `max(حد الموظفين، عدد المالكين)`. إذا كان الحد `-1` يبقى الجميع.

**القنوات** (من غير الموقوفة بسبب الباقة):

1. تُستبعد القنوات التي **نوعها غير مسموح** في الباقة الجديدة، حتى لو اختارها العميل.
2. من القنوات المؤهلة: ما اختاره العميل أولًا.
3. ما تبقّى يُملأ بالأقدم إنشاءً (`createdAt`).
4. العدد النهائي = حد القنوات. إذا كان الحد `-1` تبقى جميع القنوات المؤهلة.

لماذا يُعاد الحساب عند التنفيذ؟ لأن البيانات قد تتغير بين الجدولة والموعد: قد يُحذف موظف اختاره العميل، أو تُضاف قناة جديدة. الخوارزمية تصحح ذلك تلقائيًا.

## ٨. التحقق من الطلبات (جدولة وتعديل)

| القاعدة | الرفض |
|---|---|
| يوجد اشتراك فعّال (`status = 'active'`) | 409 |
| الباقة الجديدة موجودة و`active` وليست `enterprise` | 422 |
| التغيير تخفيض حسب القسم ٥ | 422 — الترقية لها مسار آخر |
| كل معرّف في `keepAgentIds` لموظف لدى العميل وغير موقوف | 422 |
| كل معرّف في `keepChannelIds` لقناة لدى العميل وغير موقوفة | 422 |
| لا قناة في `keepChannelIds` نوعها غير مسموح في الباقة الجديدة | 422 |
| عدد الموظفين غير المالكين في `keepAgentIds` + المالك ≤ حد الموظفين | 422 |
| عدد `keepChannelIds` ≤ حد القنوات | 422 |
| عند وجود تجاوز: العدد **يساوي** المطلوب بالضبط (`min(الحد، عدد المؤهلين)`) | 422 |

الواجهة تمنع زر التأكيد حتى يطابق العدد المطلوب، لكن على الباك إند أن يتحقق بنفسه.

## ٩. المهمة المجدولة (Job)

تعمل في الواجهة كل دقيقة. في الباك إند يكفي أن تعمل مرة كل ساعة أو أقل، على كل اشتراك فعّال لديه `scheduledChange`.

### ٩.١ التذكير — قبل الموعد بثلاثة أيام

**الشرط:** `now >= effectiveAt - 3 أيام` و`remindedAt` فارغ.

**ما يحدث:**

1. ضبط `remindedAt = now`، حتى لا يتكرر التذكير.
2. إرسال إشعار للعميل:
   - **العنوان:** `سيتم تحويل باقتك إلى {اسم الباقة} في {التاريخ}`
   - **النص:** `راجع الموظفين والقنوات التي ستبقى مفعّلة، أو ألغِ التخفيض قبل الموعد.`
   - **الرابط:** `/billing`

إذا جُدوِل التخفيض قبل أقل من ثلاثة أيام من الموعد، يُرسل التذكير في أول تشغيل للمهمة.

### ٩.٢ التنفيذ — عند `now >= effectiveAt`

ينفَّذ بالترتيب التالي، **ويُفضَّل أن يكون داخل معاملة (transaction) واحدة**:

1. **حساب ما يبقى:** `resolveKeep(newPlan, agents, channels, { keepAgentIds, keepChannelIds })`.
2. **الموظفون:**
   - الدعوة المعلّقة (`pending`) غير المختارة **تُسحب (تُحذف)**.
   - الموظف غير المختار وغير الموقوف أصلًا يُوقف: `invitationStatus = 'suspended'` و`planSuspended = true` و`status = 'offline'`.
   - إنهاء جلسات الموظفين الموقوفين.
   - الموظف الموقوف يدويًا من قبل يبقى كما هو، ولا يُضبط له `planSuspended`.
3. **القنوات:** كل قناة غير مختارة وغير موقوفة أصلًا: `status = 'disconnected'` و`planSuspended = true`، وتتوقف عن استقبال الرسائل.
4. **الاشتراك:**
   - `planId` و`billingCycle` ← من `scheduledChange`.
   - `amount` ← سعر الباقة الجديدة لدولة العميل ودورة الفوترة.
   - `currentPeriodStart = effectiveAt`.
   - `currentPeriodEnd = effectiveAt + شهر` (أو سنة إذا كانت الدورة سنوية).
   - حذف `scheduledChange` و`discount`.
5. **الفاتورة:** تحصيل الفاتورة المجدولة من وسيلة الدفع المحفوظة، ثم `status = 'paid'` و`paidAt = now`.
6. **العميل:**
   - `planId` ← الباقة الجديدة.
   - `status = 'active'`.
   - `mrr` = السعر الشهري، أو السعر السنوي ÷ ١٢.
7. **الإشعار:**
   - **العنوان:** `تم تحويل باقتك إلى {اسم الباقة}`
   - **النص:** `تم إيقاف ما يتجاوز حدود الباقة دون حذف، وسيعود تلقائيًا عند الترقية.`
   - **الرابط:** `/billing`

**لا يُحذف أي شيء** عدا الدعوات المعلّقة غير المختارة. المحادثات وجهات الاتصال والسجلات للموظفين والقنوات الموقوفة تبقى كما هي.

### ٩.٣ حصة المحادثات الشهرية

الحصة الشهرية للمحادثات تُحسب من بداية الفترة (`currentPeriodStart`). لذلك تبدأ نافذة جديدة من تاريخ التحويل، بحد الباقة الجديدة.

### ٩.٤ التجديد

عند نهاية الفترة، **التحويل المجدول يحل محل التجديد على الباقة القديمة**. لا تُصدر فاتورة تجديد بالسعر القديم إذا وُجد `scheduledChange`.

في الواجهة، إذا جُدِّد الاشتراك يدويًا قبل الموعد، ينتقل `effectiveAt` إلى نهاية الفترة الجديدة. القاعدة هي أن التحويل يحدث دائمًا عند نهاية الفترة الجارية.

## ١٠. الفاتورة المجدولة

| الحقل | القيمة |
|---|---|
| `status` | `scheduled` |
| `subscriptionId` | الاشتراك الحالي |
| `amount` | سعر الباقة الجديدة لدولة العميل وللدورة المختارة |
| `tax` | `round(amount × 5%)` |
| `total` | `amount + tax` |
| `dueDate` | `effectiveAt` |
| `items[0].description` | `اشتراك {اسم الباقة} — شهري` أو `اشتراك {اسم الباقة} — سنوي` |
| `notes` | `مجدولة — تبدأ عند انتهاء الباقة الحالية في {التاريخ}` |

- **عند إعادة الجدولة:** تُحذف الفاتورة المجدولة السابقة وتُنشأ واحدة جديدة.
- **عند الإلغاء:** تُحذف.
- **عند التنفيذ:** تُحصَّل وتصبح `paid`.

**قرار مطلوب من الباك إند:** فشل التحصيل في يوم التحويل غير مغطّى في الواجهة. المقترح: تُنفَّذ خطوات التحويل كما هي، وتصبح الفاتورة `failed`، ويدخل الاشتراك مسار `past_due` المعتاد.

## ١١. بعد التحويل

### ١١.١ الإضافة وإعادة التفعيل اليدوي

- إضافة موظف أو قناة تُفحص مقابل الحد بالعدّ الموضح في القسم ٤.
- **إعادة تفعيل موظف موقوف يدويًا** تُرفض إذا بلغ الحد. عند قبولها يُحذف `planSuspended`.
- **استئناف قناة موقوفة بسبب الباقة** يُرفض في حالتين:
  - بلوغ حد القنوات.
  - نوع القناة غير مسموح في الباقة الحالية.

  عند قبول الاستئناف يُحذف `planSuspended`.

### ١١.٢ الاستعادة التلقائية عند الترقية

تحدث **فقط** عندما ترتفع رتبة الباقة (`tier`)، وليس عند تحرير مقعد على الباقة نفسها:

1. **الموظفون:** كل من لديه `planSuspended = true` يعود (`invitationStatus = 'active'` وحذف `planSuspended`) حتى امتلاء الحد الجديد. الأقدم أولًا.
2. **القنوات:** كل قناة لديها `planSuspended = true` ونوعها مسموح في الباقة الجديدة تعود (`status = 'connected'` وحذف `planSuspended`) حتى امتلاء الحد. الأقدم إنشاءً أولًا.
3. ما أوقفه العميل يدويًا (بدون `planSuspended`) **لا يعود تلقائيًا**.

القنوات التي تحتاج إعادة مصادقة مع المزوّد (مثل انتهاء التوكن) يجب أن تُعاد بحالة تطلب إعادة الربط بدل `connected`. هذا قرار للباك إند لأن الواجهة لا تحاكيه.

## ١٢. خارج النطاق حاليًا

- **عرض الاحتفاظ (Retention offer):** خصم يُعرض على العميل للبقاء على باقته بدل التخفيض. نُفِّذ في الواجهة ثم **عُطِّل** (`offerAvailable = false` في `DowngradeDialog.tsx`، وبطاقة إعداده معلّقة في `src/pages/admin/Plans.tsx`). عند تفعيله لاحقًا:
  - الإعداد العام: `{ enabled, percent, periods }`، والافتراضي `30%` لمدة `3` فترات.
  - يُعرض مرة واحدة لكل عميل (قائمة `retentionOfferUsedBy`).
  - القبول يلغي التخفيض المجدول وفاتورته، ويضبط `subscription.discount`.
  - كل تجديد ينقص `periods` واحدًا، ويُحذف الخصم عند انتهائها أو عند تنفيذ أي تحويل.
- **تقييد المزايا (Feature gating):** النافذة تعرض المزايا التي سيفقدها العميل، لكن الواجهة لا تمنع أي ميزة فعليًا بحسب الباقة. إذا كان المطلوب تقييدها فهذا عمل منفصل.
- **تغيير دورة الفوترة على الباقة نفسها:** غير مدعوم في هذا المسار.

---

## ١٣. قائمة اختبار سريعة للباك إند

- [ ] جدولة تخفيض بلا تجاوز: لا قوائم `keep`، والفاتورة `scheduled` بتاريخ نهاية الفترة، ولا تغيير على الموظفين أو القنوات.
- [ ] جدولة مع تجاوز: رفض عدد أقل أو أكثر من المطلوب، ورفض قناة نوعها غير مسموح، والمالك يبقى دائمًا.
- [ ] إعادة الجدولة تستبدل الفاتورة السابقة ولا تضيف فاتورة ثانية.
- [ ] الإلغاء يحذف `scheduledChange` والفاتورة.
- [ ] التذكير يُرسل مرة واحدة فقط.
- [ ] التنفيذ:
  - [ ] الدعوات المعلّقة غير المختارة تُحذف.
  - [ ] الموظفون والقنوات غير المختارة تتوقف مع `planSuspended`.
  - [ ] الاشتراك والعميل يتحدثان.
  - [ ] الفاتورة تصبح `paid`.
  - [ ] الإشعار يُرسل.
- [ ] موظف مختار حُذف قبل الموعد: يُملأ مكانه بالأقدم.
- [ ] الموقوفون لا يُحتسبون في الحد، والإضافة الجديدة ممكنة تحت الحد.
- [ ] الترقية تعيد ما أوقفه التخفيض فقط، في حدود الباقة الجديدة وأنواع قنواتها.
